## 一、系统概述与目标

### 1.1 项目背景

当前软件项目开发仍存在大量重复性劳动：需求分析、文档编写、原型设计、UI 出图、技术方案撰写及初始代码搭建。本系统旨在利用 AI Agent 技术，构建一个从"用户输入需求"到"自动生成可运行项目代码"的全流程自动化接项目平台。

### 1.2 系统目标

| 目标维度 | 描述 |
|----------|------|
| **自动化程度** | 用户仅需输入自然语言项目需求，系统自动完成从分析到代码生成的全流程 |
| **交付物** | 需求文档(.md)、产品原型(Html)、UI设计稿(Html/Component)、技术执行方案(.md)、项目初始化代码 |
| **技术栈** | 后端 Spring Boot 3.x + Langchain4j + Langgraph4j，前端 Vue3 |
| **智能程度** | AI Agent 理解上下文、自主学习、支持多轮对话纠偏 |
| **可扩展性** | 工作流节点可插拔，支持自定义 Agent 能力扩展 |

### 1.3 核心工作流：递进式「生成-预览-修改/更新」模式

系统采用**递进式生成流程**，每个交付阶段均遵循标准模式：**AI 自动生成 → 用户在线预览 → 反馈修改/更新 → AI 重新生成**，确保中间产物可核查、可纠偏，避免错误向后传导。

```
用户选择模板+功能+排版+填写需求
    │
    ▼
┌─────────────────────────────────────────────────────────────────────┐
│  阶段一：需求阶段（Requirements Phase）                                │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────────┐   │
│  │ AI 自动   │ → │ 在线预览  │ → │ 标注修改  │ → │ AI 重新生成  │   │
│  │ 生成PRD   │    │ MD文档   │    │ /补充需求 │    │ 更新PRD文档  │   │
│  └──────────┘    └──────────┘    └──────────┘    └──────────────┘   │
│       ↑                                              │              │
│       └────────── 用户确认后进入下一阶段 ──────────────┘              │
└──────────────────────────┬──────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│  阶段二：原型阶段（Prototype Phase）                                   │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────────┐   │
│  │ AI 基于  │ → │ 可视化    │ → │ 交互修改  │ → │ AI 重新生成  │   │

│       ↑                                              │              │

└──────────────────────────┬──────────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│  阶段三：UI设计阶段（UI Design Phase）                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────────┐   │
│  │ AI 基于  │ → │ UI效果    │ → │ 样式调整  │ → │ AI 重新生成  │   │
│  │ 原型+PRD │    │ 预览      │    │ 配色/组件  │    │ 更新UI稿     │   │

            │  → 代码生成 → 质量检查 → 输出  │
            │  （同样遵循生成-预览-更新模式） │
            └──────────────────────────────┘
```

**模式要点：**

| 要素 | 说明 |
|------|------|
| **自动生成** | AI Agent 基于已有交付物（或用户原始输入）自动生成当前阶段产物 |
| **在线预览** | 支持在线渲染预览，无需下载即可查看完整交付物效果（MD渲染、HTML内嵌预览、UI效果预览） |
| **反馈修改** | 用户在预览界面直接标注修改意见、补充需求细节，或通过可视化编辑器调整 |
| **AI重新生成** | AI 根据用户反馈增量更新交付物，非全量重建，保持已有内容一致性 |
| **确认推进** | 用户确认当前阶段交付物后方可进入下一阶段，亦可随时回退修改 |

### 1.3.1 传统工作流概览（底层 Agent 链）

```
用户输入需求 → [需求解析Agent] → [文档生成Agent] → [原型生成Agent]
    → [UI设计Agent] → [技术方案Agent] → [整合Agent]
    → [代码生成Agent] → 输出完整项目
```

### 1.4 用户角色与权限体系

系统采用 **RBAC（基于角色的访问控制）** 模型，支持细粒度权限管理。

| 角色 | 权限描述 |
|------|----------|
| **超级管理员** | 系统全局配置、用户管理、角色管理、菜单管理、权限分配、数据维护 |
| **管理员** | 用户管理、项目模板管理、Agent 配置、系统监控、日志查看 |
| **运营人员** | 项目审核、模板管理、数据统计分析 |
| **普通用户** | 创建项目需求、查看项目进展、下载交付物、多轮对话修改需求 |

**权限控制粒度**：

```
用户(User) ──N:M──> 角色(Role) ──N:M──> 菜单权限(Menu)
                                    └──N:M──> 接口权限(API Permission)
```

- **菜单权限**：控制前端页面/按钮的可见性（树形结构，支持目录-菜单-按钮三级）
- **接口权限**：控制后端 API 的访问权限（URL + 请求方法粒度的鉴权）
- **数据权限**：控制用户可访问的数据范围（扩展能力，V1.1 实现）

**职责**：项目创建、状态流转、交付物管理

#### 2.2.2 AI 工作流引擎 `workflow-engine`

**职责**：基于 Langgraph4j 编排 AI 工作流，管理节点执行与状态

| 功能点 | 描述 |
|--------|------|
| 工作流定义 | 预定义 7 节点工作流（需求解析→代码生成） |
| 节点调度 | 按 DAG 依赖顺序执行各 Agent 节点 |
| 状态持久化 | 每个节点执行结果写入 ES，支持断点续跑 |
| 条件路由 | 根据节点输出决定下一步（如质量检查失败回退） |

##### 2.2.3.1 递进式「生成-预览-修改/更新」模式详解

**工作流预览界面（统一交互入口）**

所有阶段的「生成-预览-修改/更新」流程均通过统一的工作流预览界面进行操作。该界面采用左右分栏布局：

| 区域 | 位置 | 功能描述 |
|------|------|----------|
| **AI 对话面板** | 左侧（固定宽度 380px） | 与 AI Agent 进行自然语言对话，输入修改需求、补充说明或询问问题；支持快捷指令一键发送常见修改请求；展示完整的对话历史上下文 |
| **流程效果预览** | 右侧（自适应剩余宽度） | 实时展示当前阶段 AI 生成的交付物变更内容，包括：变更摘要表格（更新位置 + 变更内容）、代码 Diff 视图（新增/删除/修改行高亮）、阶段状态标识（生成中/预览中/已确认） |
| **操作按钮栏** | 预览区底部 | **确认** 按钮：确认当前变更，推进至下一阶段；**撤回** 按钮：回退本次变更，恢复至上版本状态；**跳过预览** 按钮：直接确认进入下一阶段 |
| **任务列表** | 底部（可折叠） | 展示当前阶段的所有任务项及完成状态，支持查看关联的生成文件清单 |

###### 阶段一：需求阶段（Requirements Phase）

用户提交项目需求后，AI 自动生成结构化的 PRD 需求规格说明书，支持在线预览与内容迭代更新。

```
┌──────────────────────────────────────────────────────────────────┐
│                     需求阶段完整交互流程                             │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Step 1: AI 自动生成 PRD（DOC_GENERATING）                        │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │ 输入：用户原始需求文本 + 模板功能配置 + 技术栈偏好             │  │
│  │ AI处理：需求解析 → 结构化提取 → 按PRD模板生成完整文档         │  │
│  │ 输出：Markdown格式PRD文档（含项目概述、功能需求、非功能需求、   │  │
│  │       验收标准、模块划分、数据流图描述）                       │  │
│  │ 耗时：60-180秒（依需求复杂度）                                │  │
│  └────────────────────────────────────────────────────────────┘  │
│                           ▼                                      │
│  Step 2: 在线预览 PRD 文档（DOC_PREVIEWING）                      │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │ 预览方式：在线 Markdown 渲染预览，支持目录跳转               │  │
│  │ 预览内容：完整需求规格说明书，含所有章节                     │  │
│  │ 用户操作：                                                 │  │
│  │  ├─ 逐章节阅读审阅                                         │  │
│  │  ├─ 对需修改处点击「标注」按钮，弹出编辑框                  │  │
│  │  ├─ 直接在文档内修改文字内容                                │  │
│  │  ├─ 添加补充需求描述/验收条件                               │  │
│  │  └─ 整体确认无误后点击「确认进入下一阶段」                  │  │
│  │ 版本管理：每次修改/更新自动生成新版本 v1.0 → v1.1 → ...     │  │
│  └────────────────────────────────────────────────────────────┘  │
│                           ▼                                      │
│  Step 3: 用户反馈修改（DOC_UPDATING）                             │
```

##### 2.2.5.1 登录认证

| 功能点 | 描述 |
|--------|------|
| 账号密码登录 | 用户名(邮箱) + 密码，BCrypt 加密验证 |
| JWT Token 签发 | 登录成功返回 AccessToken(2h) + RefreshToken(7d) |
| Token 刷新 | 使用 RefreshToken 换取新的 AccessToken |
| Token 验证拦截 | Spring Security Filter 拦截所有请求，校验 Token 有效性 |
| 登录状态维护 | 前端 Axios 拦截器自动附加 Token，401 时自动跳转登录页 |
| 登出 | 清除 Token，加入黑名单（Redis） |
| 密码修改 | 旧密码验证 + 新密码设置 |
| 登录日志 | 记录登录 IP、时间、设备信息 |

**登录认证流程图**：

```
┌──────────┐    POST /auth/login     ┌──────────────┐
│  前端     │ ──────────────────────> │  认证服务      │
│  Login   │ <────────────────────── │  AuthService  │
│  Page    │   {accessToken,         └──────┬───────┘
└──────────┘    refreshToken, user}        │
       │                                    ▼
       │ 存储Token到localStorage    ┌──────────────┐
       │ ┌────────────────────────> │  JWT Filter  │
       │ │  每次请求携带             │  (拦截器)     │
       │ │  Authorization Header    └──────┬───────┘
       │ │                                │
       ▼ ▼                      校验Token  │ 解析角色权限
┌──────────────┐                 ┌────────┴────────┐
│  Axios       │                 │  SecurityContext │
│  Interceptor │                 │  (安全上下文)     │
│  401 → 跳转  │                 └────────┬────────┘
│  登录页      │                          │
└──────────────┘                 ┌────────┴────────┐
                                 │  @PreAuthorize   │
                                 │  方法级鉴权       │
                                 └─────────────────┘
```

```json
  "exp": 1718107200

```

```
    ▼

    │
    ▼

    │
    ▼
```

#### 2.2.6 模板管理模块 `template-management`

**职责**：管理项目模板、功能项库、排版规则库三大核心资产，三者解耦设计确保配置灵活可复用。

##### 2.2.6.1 整体架构：模板-功能-排版三层解耦

```
┌─────────────────────────────────────────────────────────────┐
│                    模板管理模块架构                            │
├───────────────────┬───────────────────┬─────────────────────┤
│   项目模板(Template)│  功能项库(Module)  │  排版规则库(Layout)   │
│   - 模板名称       │   - 模块名称       │   - 布局名称         │
│   - 模板分类       │   - 模块标识       │   - 布局类型         │
│   - 模板描述       │   - 模块描述       │   - 布局预览图       │
│   - 预设技术栈     │   - 所属领域       │   - CSS/配置JSON     │
│   - 关联功能项 ▸   │   - 默认必选/可选  │   - 适用场景描述     │
│   - 关联排版规则 ▸ │   - 图标/标签      │                     │
│   - 启用状态       │   - 启用状态       │   - 启用状态         │
├───────────────────┼───────────────────┼─────────────────────┤
│  TemplateFunction  │  独立实体，         │  独立实体，          │
│  (多对多关联表)     │  不绑定任何模板     │  不绑定任何模板       │
│                   │  可被多模板共享      │  可被多模板共享       │
└───────────────────┴───────────────────┴─────────────────────┘
```

**核心设计理念**：
- **功能项库独立**：功能模块作为独立实体，不属于任何单一模板，可跨模板自由组合
- **排版规则库独立**：排版/布局方案作为独立配置，模板与排版多对多关联
- **模板 = 功能项组 + 排版规则 + 预设技术栈**：模板仅作为"配置组合器"，不持有功能项的所有权

##### 2.2.6.7 功能管理（Features）`feature-management`

**设计理念**：功能管理与功能项库不同——功能项库管理的是"可用的功能模块单元"（如用户认证、商品管理等），而功能管理是对"系统功能点"进行层级树状组织，用于定义某个模板/项目下具体包含哪些可配置的功能点，支持父子级联关系的功能树。

| 功能点 | 描述 |
|--------|------|
| 功能树查询 | 返回完整功能树（支持多层嵌套），按 sortOrder 排序，递归构建 |
| 新增功能 | 选择父级功能，填写名称、标识、描述、图标、排序号，支持指定关联模板 |
| 编辑功能 | 修改功能名称、标识、描述、图标、排序号、父级节点、关联模板 |
| 删除功能 | 级联删除子功能（需确认），已被模板关联的功能提示解除绑定后删除 |
| 启用/停用 | 单个功能启用/停用切换，停用后关联模板中该功能点不可见 |
| 层级排序 | 支持同级拖拽排序，修改 sortOrder 字段实现顺序调整 |
| 批量操作 | 批量启用/停用功能，批量移动至指定父节点，批量关联/解绑模板 |
| 模板关联映射 | 建立功能与模板的多对多关联关系，展示模板已关联功能列表，支持增删关联 |

## 三、项目模板与功能排版配置系统

### 3.1 核心设计原则

| 原则 | 说明 |
|------|------|
| **解耦设计** | 功能项、排版规则、项目模板三者独立建模，通过关联表建立多对多关系，互不耦合 |
| **可复用** | 一个功能项可被多个模板引用，一个排版规则可被多个模板使用，降低冗余 |
| **灵活组合** | 用户在创建项目时可基于模板默认配置做增量调整，无需管理员预定义所有组合 |
| **配置即代码** | 排版规则以 JSON 格式存储，前端解析渲染，支持在线预览 |
| **扩展开放** | 新增功能项或排版规则无需修改模板表结构，仅需插入数据和关联 |

### 3.2 功能项模块设计

**功能项（FunctionModule）**是系统中最小的可配置功能单元，代表一个独立的业务能力。

```json
// 功能项示例
{
  "moduleId": "md-uuid-001",
  "moduleName": "用户认证",
  "moduleKey": "USER_AUTH",          // 唯一标识，用于代码/文档引用
  "description": "用户注册、登录、密码找回等认证相关功能",
  "domain": "GENERAL",               // 所属领域：GENERAL/ECOMMERCE/CMS/MINI_PROGRAM/ADMIN
  "icon": "safety",
  "tags": ["认证", "安全", "基础"],
  "isCore": true,                     // 是否核心模块（核心模块建议默认勾选）
  "sortOrder": 1,
  "isActive": true
}
```

**排版规则（LayoutRule）**定义了页面的宏观布局骨架，以 JSON 配置格式存储。

```json

      "width": 220,                   // 侧边栏宽度（px）

      "menuAccordion": true,          // 手风琴模式
      "showIcons": true
    },
    "content": {
      "maxWidth": "100%",             // 内容区最大宽度

    "themeColors": {
      "primary": "#4F46E5",
```

**预置排版类型**：

| LayoutType | 名称 | 典型页面结构 |
|------------|------|-------------|
| `SidebarLayout` | 经典侧边栏 | `[Header] [Sidebar \| Content] [Footer?]` |

| `MixedNav` | 混合导航 | `[TopNav] [SideSubNav \| Content]` |

| `TabBarLayout` | 底部Tab | `[TitleBar] [Content] [TabBar]` |
| `FullScreen` | 全屏 | `[FullscreenContent]` |

SSE 事件类型：

| Event | 数据内容 | 触发时机 |
|-------|----------|----------|
| `stage:start` | `{ stage, timestamp }` | 节点开始执行 |
| `stage:progress` | `{ stage, percent, message }` | 节点执行中 |
| `stage:complete` | `{ stage, result: {...}, timestamp }` | 节点生成完成 |
| `stage:error` | `{ stage, error, retryable }` | 节点失败 |
| `preview:ready` | `{ stage, previewUrl, deliverableId }` | 交付物预览就绪，等待用户审核 |
| `update:start` | `{ stage, message }` | 用户提交修改，AI 开始增量更新 |
| `update:complete` | `{ stage, newVersion, previewUrl }` | 修改完成，新版本预览就绪 |
| `phase:confirmed` | `{ stage, nextStage }` | 用户确认当前阶段，自动推进至下一阶段 |
| `workflow:complete` | `{ projectId, deliverables }` | 工作流全部完成 |
| `clarification:needed` | `{ questions: [...] }` | 需要用户澄清 |


## 九、RBAC 权限模型详细设计

### 9.1 权限模型概述

系统采用 **RBAC（Role-Based Access Control）** 模型，核心实体关系如下：

```
┌──────────┐    N:M     ┌──────────┐    N:M     ┌──────────┐
│   User   │ ────────>  │   Role   │ ────────>  │   Menu   │
│  (用户)   │ <────────  │  (角色)   │ <────────  │  (菜单)   │
└──────────┘  UserRole  └──────────┘  RoleMenu  └──────────┘
                                    │
                                    │ N:M (RoleApi)
                                    ▼
                              ┌──────────┐
                              │ API Perm │
                              │ (接口权限) │
                              └──────────┘
```

**权限判定公式**：

```
用户最终权限 = Σ(用户所有角色的菜单权限) ∪ Σ(用户所有角色的接口权限)
```

### 9.2 登录认证流程

```
 │                    │                     │                       │

 │                    │───────────────────>│                       │
 │                    │                     │  JWT Filter 拦截       │
 │                    │                     │  ├── Token 过期 → 401  │
 │                    │                     │  ├── 黑名单命中 → 401  │
```


### 9.5 前端路由拦截流程

```
┌──────────────────────────────────────────────────────────────────┐
│                     前端路由守卫与菜单渲染                          │
└──────────────────────────────────────────────────────────────────┘

App 启动
    │
    ├── localStorage 中有 Token?
    │   ├── 否 → 跳转 /login
    │   └── 是 ↓
    │
    ▼
调用 GET /api/v1/auth/me 验证Token有效性
    │
    ├── 401/过期 → 清除Token，跳转 /login
    └── 200 ↓
    │
    ▼
调用 GET /api/v1/auth/menus 获取用户菜单树
    │
    ▼
动态注册路由 (router.addRoute)
    │
    ▼
渲染 Sidebar（仅显示用户有权限的菜单项）
    │
    ▼
用户点击菜单 → 路由跳转
    │
    ▼
页面内按钮权限控制 (v-permission 指令)
    │
    ▼
    ├── 有权限 → 显示按钮
    └── 无权限 → 隐藏按钮

【路由守卫伪代码】
router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('accessToken')
  if (to.path === '/login') {
    token ? next('/') : next()
  } else {
    if (!token) {
      next('/login?redirect=' + to.path)
    } else {
      const perms = store.state.user.permissions
      if (to.meta.permission && !perms.includes(to.meta.permission)) {
        next('/403') // 无权限页面
      } else {
        next()
      }
    }
  }
})
```

### 9.6 Axios 拦截器设计

```
┌─────────────────────────────────────────────────────────────┐
│                    Axios 请求/响应拦截                        │
└─────────────────────────────────────────────────────────────┘

【请求拦截器】
axios.interceptors.request.use(config => {
  const token = localStorage.getItem('accessToken')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

【响应拦截器】
axios.interceptors.response.use(
  response => response,
  error => {
    if (error.response?.status === 401) {
      // Token 过期，尝试刷新
      return refreshToken().then(newToken => {
        localStorage.setItem('accessToken', newToken)
        error.config.headers.Authorization = `Bearer ${newToken}`
        return axios(error.config)  // 重试原请求
      }).catch(() => {
        // 刷新失败，跳转登录
        localStorage.clear()
        window.location.href = '/login'
      })
    }
    if (error.response?.status === 403) {
      // 无权限提示
      ElMessage.error('您没有操作权限')
    }
    return Promise.reject(error)
  }
)
```

### 9.7 权限缓存策略

| 缓存项 | 存储位置 | TTL | 刷新时机 |
|--------|----------|-----|----------|
| 用户菜单树 | Redis `menu:tree:{userId}` | Token有效期 | 角色权限变更时清除 |
| 用户接口权限列表 | Redis `api:perms:{userId}` | Token有效期 | 角色权限变更时清除 |
| 角色-菜单关联 | Redis `role:menus:{roleId}` | 永久 | 权限分配时更新 |
| 角色-API关联 | Redis `role:apis:{roleId}` | 永久 | 权限分配时更新 |
| Token 黑名单 | Redis `token:blacklist:{tokenHash}` | Token剩余有效期 | 用户登出时加入 |
