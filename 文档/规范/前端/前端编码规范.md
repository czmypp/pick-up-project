## 一、TypeScript 编码规范

### 1.1 接口与类型命名

```typescript
// ✅ 推荐：接口用 PascalCase
interface ProjectItem {
  id: string
  name: string
  status: ProjectStatus
  progress: number
}

// ✅ 推荐：类型别名用于联合类型
type ProjectStatus = 'DRAFT' | 'RUNNING' | 'COMPLETED' | 'FAILED'

// ✅ 推荐：枚举用于固定值集合（需要运行时引用时）
enum WorkflowStage {
  REQUIREMENT_PARSING = 'REQUIREMENT_PARSING',
  DOC_GENERATING = 'DOC_GENERATING',
}

// ❌ 避免：I 前缀（如 IProjectItem），不符合 Vue 3 生态习惯
```

### 1.2 常量命名

```typescript
// ✅ 推荐：全大写 + 下划线
const MAX_UPLOAD_SIZE = 10 * 1024 * 1024
const DEFAULT_PAGE_SIZE = 20

// ✅ 推荐：const 对象用于枚举替代
const PROJECT_STATUS_MAP = {
  DRAFT: '草稿',
  RUNNING: '执行中',
  COMPLETED: '已完成',
  FAILED: '失败',
} as const

type ProjectStatus = keyof typeof PROJECT_STATUS_MAP
```

### 1.3 函数签名

```typescript
// ✅ 推荐：明确返回类型
async function fetchProjectList(params: PageParams): Promise<PageResult<ProjectResponse>> { ... }

// ✅ 推荐：可选参数使用 ?
function searchProjects(keyword: string, status?: ProjectStatus): Promise<ProjectResponse[]> { ... }

// ✅ 推荐：对象参数解构
function formatDate({ date, format = 'YYYY-MM-DD' }: { date: string; format?: string }): string { ... }

// ❌ 避免：any 类型（除非确实无法推断）
// ❌ 避免：超过 3 个参数不使用对象包装
```

### 1.4 类型文件组织

- **领域类型**：`types/[domain].d.ts`（`project.d.ts`、`workflow.d.ts`）
- **API 类型**：`types/api.d.ts`（`ApiResponse`、`PageResult`）
- **全局声明**：`types/global.d.ts`（模块声明、扩展 Window）
- **自动生成**：`types/components.d.ts`（`unplugin-vue-components` 生成，纳入 `.gitignore` 可选）
- 类型文件禁止包含运行时逻辑

## 二、Vue 组件编码规范

### 2.1 组件结构顺序

组件内代码严格按以下顺序组织：

```vue
<script setup lang="ts">
// 1. 类型导入
import type { WorkflowStage } from '@/types'

// 2. 库导入
import { ref, computed, watch, onMounted } from 'vue'

// 3. Props 定义（使用泛型）
interface Props {
  stages: WorkflowStage[]
  loading?: boolean
}
const props = withDefaults(defineProps<Props>(), {
  loading: false
})

// 4. Emits 定义
const emit = defineEmits<{
  retry: [stageName: string]
  refresh: []
}>()

// 5. Composables
const { isConnected, connect } = useSSE()

// 6. 响应式状态
const selectedStage = ref('')
const isPanelVisible = ref(false)

// 7. 计算属性
const filteredStages = computed(() =>
  props.stages.filter(s => s.status !== 'PENDING')
)

// 8. 方法
function handleRetry(stageName: string) {
  emit('retry', stageName)
}

// 9. 监听器
watch(() => props.stages, (val) => {
  if (val.every(s => s.status === 'COMPLETED')) {
    emit('refresh')
  }
})

// 10. 生命周期
onMounted(() => {
  // 初始化逻辑
})
</script>

<template>
  <!-- 模板 -->
</template>

<style scoped>
/* 样式 */
</style>
```

### 2.2 SFC 规范要求

- **必须**使用 `<script setup lang="ts">` + Composition API
- **必须**使用 TypeScript，禁止纯 `.js` / `.vue`（无 `lang="ts"`）
- **必须**使用 `<style scoped>` 进行样式隔离
- Props 使用 `defineProps<T>()` 泛型语法，Emits 使用 `defineEmits<T>()` 类型约束
- 页面级组件使用 `definePageMeta`（如需要）
- 模板中 `<script>` 在前，`<template>` 居中，`<style>` 在后

### 2.3 模板规范

```vue
<!-- ✅ 推荐 -->
<template>
  <div v-if="loading" class="project-detail">
    <AppLoading />
  </div>
  <div v-else class="project-detail">
    <h1>{{ project?.name }}</h1>
    <StatusBadge :status="project?.status" />
  </div>
</template>

<!-- ❌ 避免：模板中写复杂表达式 -->
<template>
  <div>{{ stages.filter(s => s.status === 'COMPLETED').map(s => s.displayName).join(', ') }}</div>
</template>

<!-- ✅ 替代：用 computed -->
<template>
  <div>{{ completedStageNames }}</div>
</template>
```

**规则**：
- `v-if` / `v-for` 不同时使用在同一元素
- `v-for` 必须绑定唯一 `:key`
- 复杂逻辑抽取为 `computed`，不写在模板内
- 条件渲染优先 `v-if`，频繁切换用 `v-show`

## 三、文件与目录命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| **组件文件** | PascalCase | `ProjectCard.vue`、`CreateProjectPage.vue` |
| **页面文件** | PascalCase + `Page` 后缀 | `LoginPage.vue`、`DashboardPage.vue` |
| **布局文件** | PascalCase + `Layout` 后缀 | `DefaultLayout.vue` |
| **Composable** | camelCase + `use` 前缀 | `useSSE.ts`、`usePagination.ts` |
| **Store** | camelCase + 业务名 | `user.ts`、`project.ts` |
| **API 模块** | camelCase + 业务名 | `project.ts`、`auth.ts` |
| **类型文件** | camelCase + 领域名 + `.d.ts` | `project.d.ts`、`workflow.d.ts` |
| **工具文件** | camelCase | `format.ts`、`validate.ts` |
| **目录** | kebab-case 或 小写 | `project/`、`business/` |

## 四、Pinia Store 编码规范

### 4.1 Setup Store 语法（统一使用）

```typescript
// ✅ 推荐：Setup Store（Composition API 风格）
export const useUserStore = defineStore('user', () => {
  // state → ref/reactive
  const token = ref('')
  const userInfo = ref<UserInfo | null>(null)

  // getters → computed
  const isLoggedIn = computed(() => !!token.value)

  // actions → 普通函数
  async function login(params: LoginRequest) { ... }
  function logout() { ... }

  return { token, userInfo, isLoggedIn, login, logout }
})

// ❌ 不推荐：Options Store（选项式，与本项目 Composition API 风格不一致）
```

### 4.2 Store 规范要点

- **一个 Store 一个文件**，按业务领域划分，禁止巨型 Store
- **不直接操作 localStorage**：持久化在 action 中处理，state 从 localStorage 初始化
- **API 调用隔离**：Store 不直接调 `axios`，通过 `api/modules/` 层调用
- **state 初始化类型明确**：`ref<string>('')` 而非 `ref()` 无类型推断
- **return 声明所有外部可用的 state/getter/action**

## 五、API 层编码规范

### 5.1 接口分组

```typescript
// api/modules/project.ts
export const projectApi = {
  /** 创建项目 */
  create(data: CreateProjectRequest): Promise<ProjectResponse> {
    return http.post('/projects', data)
  },

  /** 分页列表 */
  list(params: PageParams & { status?: string }): Promise<PageResult<ProjectResponse>> {
    return http.get('/projects', { params })
  },

  /** 详情 */
  detail(id: string): Promise<ProjectDetailResponse> {
    return http.get(`/projects/${id}`)
  },
}
```

### 5.2 规范要点

- 每个业务模块占一个文件（`api/modules/xxx.ts`）
- 导出对象形式 `{ method1, method2 }`，非 class
- 每个方法添加 JSDoc 注释
- 返回类型显式声明，不依赖隐式推导
- URL 中的动态参数使用模板字符串：`` `/projects/${id}` ``
- 查询参数使用 `{ params }` 对象
- 不在此层做业务逻辑处理

## 六、Composable 编码规范

### 6.1 命名与导出

```typescript
// ✅ 推荐：use 前缀 + 明确的名称
export function useSSE() { ... }
export function usePagination() { ... }
export function useDebounce(fn: Function, delay: number) { ... }

// ✅ 推荐：返回对象（便于按需解构）
return { isConnected, connect, disconnect }
```

### 6.2 规范要点

- 一个文件只导出一个 Composable
- 文件名与 Composable 名一致：`useSSE.ts` → `useSSE()`
- 内部资源在 `onUnmounted` 中清理（EventSource、定时器、事件监听）
- 参数使用对象形式（超过 2 个参数时）
- 不直接操作 DOM（用 Vue ref + 模板绑定）

## 七、样式编码规范

### 7.1 优先级体系

1. **CSS 变量**（`variables.css`）：色板、圆角、阴影、尺寸
2. **Element Plus** ：表单、表格、弹窗等标准组件
3. **UnoCSS**：原子化样式微调（`p-4`、`flex`、`gap-2`）
4. **组件 Scoped CSS**：组件特定样式
5. **禁止**：内联样式（`style="color: red"`），除非动态值

### 7.2 样式编写

```css
/* ✅ 推荐 */
.stage-timeline {
  padding: var(--spacing-4);
  border-radius: var(--radius);
  background: var(--color-bg);
}

.timeline-item.status-completed .tl-dot {
  background: var(--color-success);
}

.timeline-item.status-running .tl-dot {
  background: var(--color-primary);
  animation: pulse 1.5s infinite;
}

/* ❌ 避免：硬编码颜色值 */
.title { color: #4F46E5; }
```

### 7.3 响应式

```css
/* ✅ 推荐：移动优先 */
.container {
  display: grid;
  grid-template-columns: 1fr;
}

@media (min-width: 768px) {
  .container {
    grid-template-columns: repeat(2, 1fr);
  }
}

@media (min-width: 1024px) {
  .container {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

## 八、错误处理规范

### 8.1 API 错误分层

| 层级 | 处理方式 |
|------|----------|
| **Axios 拦截器** | 统一处理 401 跳转登录、429 限流提示、网络异常 |
| **API 模块** | 不做 try-catch，异常向上抛出 |
| **Store Action** | 捕获特殊业务错误（如配额不足），其他向上抛出 |
| **页面组件** | 最终 try-catch + 用户友好提示 |

### 8.2 异常处理示例

```typescript
// ❌ 避免：吞掉异常
async function createProject(data: CreateProjectRequest) {
  try {
    return await projectApi.create(data)
  } catch (e) {
    // 什么都不做
  }
}

// ✅ 推荐：明确处理
async function createProject(data: CreateProjectRequest) {
  try {
    loading.value = true
    const result = await projectApi.create(data)
    ElMessage.success('项目创建成功，AI 工作流已启动')
    router.push({ name: 'ProjectDetail', params: { id: result.projectId } })
  } catch (e: any) {
    if (e.code === 100004) {
      ElMessage.error('AI 配额不足，请联系管理员')
    } else {
      ElMessage.error(e.message || '创建失败，请重试')
    }
  } finally {
    loading.value = false
  }
}
```

## 九、代码审查清单

### 提交前自查

- [ ] 无 `console.log` 残留（调试日志已删除）
- [ ] 无 `any` 类型（除非绝对必要且有注释说明）
- [ ] 无硬编码的魔法数字和字符串
- [ ] 无注释掉的代码块
- [ ] Props 和 Emits 有 TypeScript 类型约束
- [ ] `<style scoped>` 样式隔离
- [ ] `v-for` 有唯一 `:key`
- [ ] 组件卸载时清理资源（SSE、定时器、事件监听）
- [ ] 无 Vue 警告（浏览器控制台检查）

### Code Review 关注点

- [ ] 组件粒度合理（单文件不超过 300 行）
- [ ] Store 职责单一（Store 不超过 150 行）
- [ ] API 层无业务逻辑
- [ ] 错误处理覆盖主路径 + 异常路径
- [ ] TypeScript 类型定义完整且准确
- [ ] 响应式数据使用正确（ref vs reactive）
- [ ] 异步操作有 loading 状态
- [ ] 空状态 / 错误状态有 UI 兜底
