### 1.2 分层职责

| 层次 | 模块 | 职责 | 依赖方向 |
|------|------|------|----------|
| **表示层** | `pick-up-api` | REST Controller、请求拦截、全局异常处理、参数校验 | → service |
| **业务层** | `pick-up-service` | 业务逻辑编排、事务管理、权限校验 | → domain, infra |
| **工作流层** | `pick-up-workflow` | Langgraph4j DAG 编排、节点调度、状态持久化、SSE 推送 | → ai-engine, domain |
| **AI 引擎层** | `pick-up-ai-engine` | Langchain4j Agent/Tool/Chain 封装、LLM 调用、提示词管理 | → infra, domain |
| **基础设施层** | `pick-up-infrastructure` | ES / Redis / Security / 存储 / 缓存等通用基础设施 | → domain |
| **领域层** | `pick-up-domain` | JPA Entity、Repository、DTO / VO、枚举常量 | 无依赖（最底层） |
| **公共层** | `pick-up-common` | 通用工具类、全局异常定义、统一响应体、常量 | 无依赖 |

### 1.3 依赖原则

```
依赖方向：api → service → domain ← infrastructure / ai-engine / workflow
                                    ↑
                               common (被所有模块依赖)
```

- **严格单向依赖**：上层可依赖下层，下层不可依赖上层
- **domain 独立**：不依赖任何业务模块，仅依赖 common
- **接口隔离**：模块间通过接口通信，具体实现在各自模块内

## 二、技术栈选型

## 四、API 设计规范

### 4.1 URL 设计原则

```
https://{domain}/api/v1/{resource}[/{resourceId}][/{subResource}]
```

| 规则 | 说明 | 示例 |
|------|------|------|
| **Base** | `/api/v1` | 版本化 API 路径 |
| **资源复数** | 统一使用复数名词 | `/projects` 非 `/project` |
| **层级关系** | 子资源用路径层级表示 | `/projects/{id}/deliverables` |
| **小写+连字符** | URL 全部小写，单词用 - 连接 | `/tech-plans` 非 `/techPlans` |
| **无动词** | 资源操作用 HTTP 方法表达 | `POST /projects` 而非 `/projects/create` |
| **无尾斜杠** | URL 末尾不加 `/` | `/projects` 非 `/projects/` |

### 4.2 HTTP 方法语义

| 方法 | 语义 | 幂等 | 安全 |
|------|------|------|------|
| `GET` | 查询资源 | ✅ | ✅ |
| `POST` | 创建资源 | ❌ | ❌ |
| `PUT` | 全量更新资源 | ✅ | ❌ |
| `PATCH` | 部分更新资源 | ❌ | ❌ |
| `DELETE` | 删除资源 | ✅ | ❌ |

### 4.3 统一响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2026-06-11T11:00:00Z",
  "traceId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

**分页响应**：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [],
    "total": 156,
    "page": 1,
    "size": 20,
    "totalPages": 8
  },
  "timestamp": "2026-06-11T11:00:00Z",
  "traceId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

### 4.4 错误码规范

| 范围 | 类别 | 说明 |
|------|------|------|
| 200 | 成功 | 请求成功 |
| 400 | 参数错误 | 请求参数校验失败 |
| 401 | 未认证 | Token 缺失或无效 |
| 403 | 无权限 | 角色权限不足 |
| 404 | 不存在 | 资源不存在 |
| 409 | 冲突 | 数据冲突（如重复创建） |
| 429 | 限流 | 请求频率超限 |
| 500 | 服务错误 | 服务器内部异常 |
| **业务错误码** | | **(6位数字)** |
| 100001 | AI 调用失败 | LLM API 调用异常 |
| 100002 | 工作流失败 | 工作流节点执行失败 |
| 100003 | 代码生成失败 | 代码生成异常 |
| 100004 | 配额不足 | 用户 AI 配额已用完 |
| 100005 | 文件存储失败 | 文件上传/写入失败 |

### 4.5 请求规范

**请求头**：
```
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
X-Request-Id: uuid-v4
Accept-Language: zh-CN
```

**分页参数**：
```
GET /api/v1/projects?page=1&size=20&sort=createdAt,desc
```

**日期时间格式**：统一 ISO 8601 `2026-06-11T11:00:00Z`（UTC 时区）

### 4.6 DTO 命名规范

```
请求: {Action}{Resource}Request     →  CreateProjectRequest
响应: {Resource}[Detail]Response     →  ProjectResponse, ProjectDetailResponse
视图: {Resource}VO                   →  ProjectVO
```

## 六、环境与配置管理

### 6.1 环境划分

| 环境 | 说明 | 配置文件 |
|------|------|----------|
| `dev` | 本地开发 | `application-dev.yml` |
| `test` | 测试环境 | `application-test.yml` |
| `staging` | 预发布环境 | `application-staging.yml` |
| `prod` | 生产环境 | `application-prod.yml` |

### 6.2 配置优先级

```
命令行参数 > 环境变量 > application-{profile}.yml > application.yml
```

### 6.3 敏感配置管理

- API Key、数据库密码等敏感信息 **不得** 硬编码或提交到仓库
- 开发环境使用 `.env` 文件（已加入 `.gitignore`）
- 生产环境使用环境变量或 Vault 等密钥管理服务

```yaml
# application.yml
spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/pickup}
    username: ${DB_USERNAME:pickup}
    password: ${DB_PASSWORD}  # 无默认值，强制从环境变量读取

langchain4j:
  open-ai:
    api-key: ${OPENAI_API_KEY}
```
