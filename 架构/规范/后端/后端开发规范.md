## 一、命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| **包名** | 全部小写，点分隔 | `com.pickup.domain.entity` |
| **类名** | 大驼峰 PascalCase | `ProjectService`, `ApiResponse` |
| **接口** | 大驼峰，不加 I 前缀 | `ProjectService`（非 `IProjectService`） |
| **抽象类** | Abstract/Base 前缀 | `AbstractAgent` |
| **实现类** | Impl 后缀 | `ProjectServiceImpl` |
| **方法名** | 小驼峰 camelCase | `createProject`, `findById` |
| **常量** | 全大写 + 下划线 | `MAX_RETRY_COUNT` |
| **变量** | 小驼峰 | `projectName`, `userId` |
| **枚举** | 大驼峰，枚举值全大写 | `ProjectStatus.RUNNING` |
| **数据库表** | `t_` 前缀 + 小写 + 下划线 | `t_project`, `t_workflow_stage` |
| **数据库列** | 小写 + 下划线 | `created_at`, `project_id` |
| **URL 路径** | 短横线分隔 kebab-case | `/api/v1/tech-plans` |

## 二、类结构规范

### 2.1 Entity 类

```java
@Entity
@Table(name = "t_project")
@Getter
@Setter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@AllArgsConstructor(access = AccessLevel.PRIVATE)
@Builder
public class Project {

    // 1. 静态常量
    private static final int MAX_RETRY = 3;

    // 2. 实例变量
    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private String id;

    @Column(nullable = false, length = 255)
    private String name;

    @Column(nullable = false, length = 50)
    @Enumerated(EnumType.STRING)
    private ProjectStatus status;

    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;

    @Column(name = "updated_at")
    private LocalDateTime updatedAt;

    // 3. JPA 回调
    @PrePersist
    protected void onCreate() {
        this.createdAt = LocalDateTime.now();
    }

    @PreUpdate
    protected void onUpdate() {
        this.updatedAt = LocalDateTime.now();
    }

    // 4. 领域方法
    public void markAsRunning() {
        validateStatusTransition(ProjectStatus.RUNNING);
        this.status = ProjectStatus.RUNNING;
    }

    public boolean isRetryable() {
        return this.retryCount < MAX_RETRY;
    }

    // 5. 私有辅助方法
    private void validateStatusTransition(ProjectStatus target) {
        // 状态转换校验逻辑
    }
}
```

**规范要点**：
- 类内顺序：静态常量 → 实例变量 → JPA 回调 → 领域方法 → 私有辅助方法
- 使用 `@Column` 显式定义约束（`nullable`, `length`, `updatable`）
- 业务状态变更封装为领域方法，不使用裸露 setter
- 时间字段使用 `@PrePersist` / `@PreUpdate` 自动填充

### 2.2 DTO 类

```java
// ✅ 推荐：Record 类型（Java 21）
public record CreateProjectRequest(
    @NotBlank(message = "项目名称不能为空")
    @Size(max = 255, message = "项目名称最长255个字符")
    String name,

    @NotBlank(message = "需求描述不能为空")
    @Size(min = 10, max = 10000, message = "需求描述10-10000个字符")
    String requirementText,

    ProjectType projectType,

    TechPreferences techPreferences,

    @Builder.Default
    boolean autoConfirm = false
) implements Serializable {}
```

- 优先使用 Java 21 `Record` 作为 DTO
- 字段级别的校验注解（Jakarta Validation）
- 可选字段提供默认值（`@Builder.Default`）

### 2.3 序列化约束（强制）

所有后端的 **Entity 实体类**、**VO 视图对象**、**入参对象（Request）** 及 **返回值对象（Response）**，必须实现 `Serializable` 接口。

```java
// ✅ 正确：Entity 实现序列化
@Entity
@Table(name = "t_project")
@Getter
@Setter
@Builder
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@AllArgsConstructor(access = AccessLevel.PRIVATE)
public class Project implements Serializable {
    private static final long serialVersionUID = 1L;
    // ... 字段
}

// ✅ 正确：DTO Record 实现序列化（Java 21）
public record CreateProjectRequest(
    @NotBlank String name,
    // ...
) implements Serializable {}

// ✅ 正确：VO 实现序列化
public class ProjectVO implements Serializable {
    private static final long serialVersionUID = 1L;
    // ... 字段
}

// ❌ 错误：未实现 Serializable
public class ProjectVO { ... }
```

**要点**：
- 所有涉及网络传输、缓存、序列化存储的对象必须实现 `Serializable`
- 建议显式声明 `serialVersionUID`（非 Record 类），避免 JVM 自动计算导致版本不兼容
- Record 类无需手动声明 `serialVersionUID`，编译器自动处理

### 2.4 内部类约束（强制）

**Entity 实体类**、**VO 视图对象**、**入参对象（Request）** 及 **返回值对象（Response）** 中，**严禁**定义或使用内部类（包括静态内部类、成员内部类、局部内部类及匿名内部类）。

```java
// ❌ 错误：在实体中定义内部类
public class Project implements Serializable {
    private Metadata metadata;      // 引用了内部类

    public static class Metadata {  // 禁止！静态内部类
        private String author;
    }
}

// ❌ 错误：在 VO 中定义内部类
public class ProjectVO implements Serializable {
    private List<TaskVO> tasks;
    private List<MemberVO> members;

    public static class TaskVO { }     // 禁止！
    public static class MemberVO { }   // 禁止！
}

// ✅ 正确：每个类独立成文件
// ── 独立文件 ProjectVO.java ──
public class ProjectVO implements Serializable { ... }

// ── 独立文件 TaskVO.java ──
public class TaskVO implements Serializable { ... }

// ── 独立文件 MemberVO.java ──
public class MemberVO implements Serializable { ... }

// ── 独立文件 ProjectMetadata.java ──
public class ProjectMetadata implements Serializable { ... }
```

**要点**：
- 内部类会导致序列化复杂度增加、反射工具兼容性问题以及代码可读性下降
- 所有嵌套的数据结构必须提取为独立的顶层类文件
- 如需分组命名，使用合理的包结构进行组织，而非内部类

## 三、Service 层编码规范

### 3.1 接口与实现分离

```java
// Service 接口 — domain 模块
public interface ProjectService {
    ProjectResponse createProject(String userId, CreateProjectRequest request);
    ProjectDetailResponse getDetail(String projectId);
    PageResult<ProjectResponse> listProjects(String userId, Pageable pageable);
}

// Service 实现 — service 模块
@Service
@Transactional(readOnly = true)
@RequiredArgsConstructor
@Slf4j
public class ProjectServiceImpl implements ProjectService {

    private final ProjectRepository projectRepository;
    private final WorkflowExecutor workflowExecutor;
    private final ProjectConverter projectConverter;

    @Override
    @Transactional
    public ProjectResponse createProject(String userId, CreateProjectRequest request) {
        // 1. 参数校验（业务校验，非 Bean Validation 能覆盖的）
        validateQuota(userId);

        // 2. 构建实体
        Project project = Project.builder()
                .name(request.name())
                .status(ProjectStatus.DRAFT)
                .userId(userId)
                .build();

        // 3. 持久化
        project = projectRepository.save(project);

        // 4. 异步启动工作流
        CompletableFuture.runAsync(() -> workflowExecutor.execute(project.getId(), request));

        // 5. 日志
        log.info("Project created: id={}, name={}, userId={}", project.getId(), project.getName(), userId);

        // 6. 返回
        return projectConverter.toResponse(project);
    }
}
```

**规范要点**：
- 接口定义在 `domain` 模块，实现在 `service` 模块
- 使用 `@RequiredArgsConstructor` 构造器注入（禁止字段注入）
- 读操作类级别 `@Transactional(readOnly = true)`，写操作方法级别覆盖 `@Transactional`
- 使用 Lombok `@Slf4j` 记录关键操作日志
- 方法内按：校验 → 业务逻辑 → 持久化 → 异步/事件 → 日志 → 返回 的顺序

### 3.2 事务边界

```java
// ✅ 推荐：事务放在 Service 层，不在 Controller 层开事务
// ✅ 读方法：类级别 @Transactional(readOnly = true)
// ✅ 写方法：方法级别 @Transactional（覆盖类级别）
// ✅ 长事务拆分：将不需要事务的操作移到事务外
// ❌ 避免：在事务方法内进行 RPC 调用、文件 IO、SSE 推送
```

## 四、Controller 层编码规范

```java
@RestController
@RequestMapping("/api/v1/projects")
@RequiredArgsConstructor
@Tag(name = "项目管理", description = "项目 CRUD 与工作流控制")
public class ProjectController {

    private final ProjectService projectService;

    @PostMapping
    @Operation(summary = "创建新项目", description = "提交需求并启动 AI 工作流")
    public ApiResponse<ProjectResponse> create(
            @Valid @RequestBody CreateProjectRequest request,
            @AuthenticationPrincipal JwtUserDetails user) {
        return ApiResponse.success(projectService.createProject(user.getId(), request));
    }

    @GetMapping("/{projectId}")
    @Operation(summary = "获取项目详情")
    public ApiResponse<ProjectDetailResponse> detail(
            @PathVariable String projectId,
            @AuthenticationPrincipal JwtUserDetails user) {
        return ApiResponse.success(projectService.getDetail(projectId));
    }

    @GetMapping
    @Operation(summary = "项目列表（分页）")
    public ApiResponse<PageResult<ProjectResponse>> list(
            @RequestParam(defaultValue = "1") int page,
            @RequestParam(defaultValue = "20") int size,
            @RequestParam(required = false) String status,
            @RequestParam(required = false) String keyword,
            @AuthenticationPrincipal JwtUserDetails user) {
        Pageable pageable = PageRequest.of(page - 1, size, Sort.by("createdAt").descending());
        return ApiResponse.success(projectService.listProjects(user.getId(), pageable));
    }
}
```

**规范要点**：
- Controller 只负责参数校验和路由，不写业务逻辑
- 使用 `@Valid` 触发 Jakarta Validation
- 使用 `@AuthenticationPrincipal` 获取当前用户
- 使用 Swagger 注解 `@Tag`, `@Operation` 生成 API 文档
- 返回统一用 `ApiResponse.success()` / `ApiResponse.error()` 包装

## 五、Repository 层编码规范

```java
@Repository
public interface ProjectRepository extends JpaRepository<Project, String>,
                                             JpaSpecificationExecutor<Project> {

    Page<Project> findByUserId(String userId, Pageable pageable);

    Optional<Project> findByIdAndUserId(String id, String userId);

    @Query("SELECT p FROM Project p WHERE p.userId = :userId AND p.status IN :statuses")
    List<Project> findByUserIdAndStatusIn(@Param("userId") String userId,
                                           @Param("statuses") List<ProjectStatus> statuses);

    @Modifying
    @Query("UPDATE Project p SET p.status = :status WHERE p.id = :id")
    int updateStatus(@Param("id") String id, @Param("status") ProjectStatus status);
}
```

**规范要点**：
- 方法命名遵循 Spring Data JPA 命名约定
- 复杂查询使用 `@Query`（JPQL），避免 Native SQL
- 写操作（`UPDATE`, `DELETE`）必须加 `@Modifying`
- 分页查询返回 `Page<T>`，参数接收 `Pageable`

## 六、异常处理规范

### 6.1 异常定义

```java
// 业务异常（在 common 模块定义）
public class BusinessException extends RuntimeException {
    private final ErrorCode errorCode;
    private final Object[] args;  // 消息参数
}

// 错误码
public enum ErrorCode {
    SUCCESS(200, "成功"),
    BAD_REQUEST(400, "参数错误"),
    UNAUTHORIZED(401, "未认证"),
    FORBIDDEN(403, "无权限"),
    NOT_FOUND(404, "资源不存在"),
    CONFLICT(409, "数据冲突"),
    RATE_LIMITED(429, "请求过于频繁"),
    INTERNAL_ERROR(500, "服务器内部错误"),

    // 业务错误码（6位）
    AI_CALL_FAILED(100001, "AI 调用失败"),
    WORKFLOW_FAILED(100002, "工作流执行失败"),
    CODE_GEN_FAILED(100003, "代码生成失败"),
    QUOTA_EXCEEDED(100004, "配额不足"),
    FILE_STORAGE_FAILED(100005, "文件存储失败");

    private final int code;
    private final String defaultMessage;
}
```

### 6.2 全局异常处理

```java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public ApiResponse<Void> handleBusinessException(BusinessException e) {
        log.warn("Business exception: code={}, msg={}", e.getErrorCode().getCode(), e.getMessage());
        return ApiResponse.error(e.getErrorCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ApiResponse<Void> handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(f -> f.getField() + ": " + f.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return ApiResponse.error(ErrorCode.BAD_REQUEST, msg);
    }

    @ExceptionHandler(Exception.class)
    public ApiResponse<Void> handleUnknown(Exception e) {
        log.error("Unknown exception", e);
        return ApiResponse.error(ErrorCode.INTERNAL_ERROR, "服务器繁忙，请稍后重试");
    }
}
```

**规范要点**：
- 异常粒度与层次：业务异常（`BusinessException`）、校验异常（Jakarta 自动）、系统异常（兜底 `Exception.class`）
- `@RestControllerAdvice` 统一拦截，避免 Controller 内 try-catch
- 生产环境不暴露堆栈信息给前端

## 七、Lombok 使用规范

```java
// ✅ 推荐：明确需要的注解
@Entity
@Getter
@Setter
@Builder
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@AllArgsConstructor(access = AccessLevel.PRIVATE)
public class Project { ... }

// Service 层
@Service
@RequiredArgsConstructor      // final 字段构造器注入
@Slf4j                        // 日志
@Transactional(readOnly = true)
public class ProjectServiceImpl { ... }

// DTO（Record 不需要 Lombok）
public record CreateProjectRequest(...) { }

// ❌ 避免：无脑 @Data
// @Data = @Getter + @Setter + @RequiredArgsConstructor + @ToString + @EqualsAndHashCode
// 风险：@ToString 循环引用、@EqualsAndHashCode 在 JPA 场景不当
```

**Lombok 注解使用清单**：

| 注解 | 使用场景 | 注意事项 |
|------|----------|----------|
| `@Getter` / `@Setter` | Entity、DTO（非 Record） | 按需使用，不设全部字段 |
| `@Builder` | Entity 构建 | 配合 `@AllArgsConstructor(PRIVATE)` |
| `@NoArgsConstructor` | JPA Entity 必需 | 访问级别 `PROTECTED` |
| `@AllArgsConstructor` | Builder 需要 | 访问级别 `PRIVATE` |
| `@RequiredArgsConstructor` | Service 构造器注入 | 仅用于 final 字段 |
| `@Slf4j` | 日志 | 全项目统一使用 |
| **禁止** `@Data` | - | 避免 JPA 循环引用问题 |
| **禁止** `@SneakyThrows` | - | 隐藏受检异常，不利于排查 |

## 八、日志规范

```java
@Slf4j
public class ProjectServiceImpl {

    public ProjectResponse createProject(String userId, CreateProjectRequest request) {
        // INFO：关键业务节点
        log.info("Creating project: name={}, userId={}", request.name(), userId);

        try {
            // ... 业务逻辑
        } catch (Exception e) {
            // ERROR：异常情况（含完整堆栈）
            log.error("Failed to create project for userId={}", userId, e);
            throw e;
        }

        // DEBUG：调试信息（生产环境不输出）
        log.debug("Project entity: {}", project);
    }
}
```

| 级别 | 场景 | 示例 |
|------|------|------|
| `ERROR` | 系统异常，需要立即关注 | AI 调用失败、数据库连接异常 |
| `WARN` | 可恢复的异常 | 配额不足、工作流重试 |
| `INFO` | 关键业务节点 | 项目创建、工作流完成、用户登录 |
| `DEBUG` | 调试信息（仅开发） | 中间变量、请求参数详情 |

**规范**：
- 禁止 `System.out.println`，统一使用 `@Slf4j`
- 日志参数使用 `{}` 占位符，不使用字符串拼接
- 异常日志必须包含堆栈（`log.error(msg, exception)`）
- 不在循环中打印 INFO 日志

## 九、Git 工作流与提交规范

### 9.1 分支策略

```
main ────────────────────────────── (生产分支)
  │
  └── develop ───────────────────── (开发主分支)
         │
         ├── feature/xxx            (功能分支)
         ├── bugfix/xxx             (修复分支)
         └── release/vX.Y.Z         (发布分支)
```

| 分支类型 | 命名格式 | 说明 | 合并目标 |
|----------|----------|------|----------|
| `main` | - | 生产环境 | 只接受 release + hotfix |
| `develop` | - | 开发主分支 | - |
| `feature/*` | `feature/{描述}` | 新功能 | → develop |
| `bugfix/*` | `bugfix/{描述}` | Bug 修复 | → develop |
| `release/*` | `release/v{版本号}` | 发布准备 | → main + develop |
| `hotfix/*` | `hotfix/{描述}` | 紧急修复 | → main + develop |

### 9.2 Commit Message 规范

采用 **Conventional Commits**：

```
<type>(<scope>): <subject>

[body]

[footer]
```

#### Type 类型

| Type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档变更 |
| `style` | 代码格式（不影响逻辑） |
| `refactor` | 代码重构 |
| `perf` | 性能优化 |
| `test` | 添加或修改测试 |
| `chore` | 构建/辅助工具变更 |
| `ci` | CI 配置变更 |
| `revert` | 回退提交 |

#### Scope 范围

| Scope | 说明 |
|-------|------|
| `ai-engine` | AI 引擎模块 |
| `workflow` | 工作流模块 |
| `service` | 业务服务模块 |
| `api` | Web 接口模块 |
| `domain` | 领域模型模块 |
| `infra` | 基础设施模块 |
| `common` | 公共模块 |
| `ui-front` | 用户端前端 |
| `ui-admin` | 管理端前端 |
| `docs` | 文档 |
| `deps` | 依赖变更 |

#### 示例

```
feat(ai-engine): 实现需求解析 Agent 及关联 Tool

- 添加 RequirementParserAgent，支持结构化需求提取
- 实现 SimilarProjectSearchTool ES 检索工具
- 添加 requirement_parser.st 提示词模板
- 单元测试覆盖核心解析逻辑

Closes #12
```

### 9.3 代码审查流程

- 所有合并到 `develop` 的 PR 需 ≥1 人 Review
- 合并到 `main` 的 PR 需 ≥2 人 Review
- PR 标题遵循 Conventional Commits 格式
- Review 检查点：代码规范、业务逻辑、测试覆盖、安全性

## 十二、编码强制约束

> **说明**：本章节约束为【强制】级别，Code Review 时作为一票否决项。违反任一约束的代码不得合并入主分支。

### 12.1 魔法值约束

代码中**严禁**直接使用字符串、数字、符号等魔法值（Magic Value），必须将其提取为**常量**或**枚举**。

```java
// ❌ 错误：魔法值散落各处
public class OrderService {
    public void processOrder(Order order) {
        if (order.getAmount() > 10000) {                    // 魔法数字
            order.setType("VIP_ORDER");                      // 魔法字符串
        }
        if (order.getStatus().equals("PENDING_PAYMENT")) {   // 魔法字符串
            // ...
        }
        if (order.getRetryCount() >= 3) {                   // 魔法数字
            order.setChannel("DEAD_LETTER");                 // 魔法字符串
        }
        doSomething("+");                                    // 魔法符号
    }
}

// ✅ 正确：提取为常量/枚举
public class OrderService {

    private static final BigDecimal VIP_ORDER_THRESHOLD = new BigDecimal("10000");
    private static final int MAX_RETRY_COUNT = 3;
    private static final String PLUS_OPERATOR = "+";

    public void processOrder(Order order) {
        if (order.getAmount().compareTo(VIP_ORDER_THRESHOLD) > 0) {
            order.setType(OrderType.VIP_ORDER.name());
        }
        if (order.getStatus() == OrderStatus.PENDING_PAYMENT) {
            // ...
        }
        if (order.getRetryCount() >= MAX_RETRY_COUNT) {
            order.setChannel(MessageChannel.DEAD_LETTER.name());
        }
        doSomething(PLUS_OPERATOR);
    }
}

// 常量类组织示例
public final class OrderConstants {
    private OrderConstants() {} // 禁止实例化

    public static final BigDecimal VIP_THRESHOLD = new BigDecimal("10000");
    public static final int MAX_RETRY = 3;
    public static final String OPERATOR_PLUS = "+";
}

// 枚举示例
public enum OrderStatus {
    PENDING_PAYMENT("待支付"),
    PAID("已支付"),
    SHIPPED("已发货"),
    COMPLETED("已完成"),
    CANCELLED("已取消");

    private final String description;
    OrderStatus(String description) { this.description = description; }
    public String getDescription() { return description; }
}
```

**豁免场景**：
- 循环索引变量 `i`, `j`, `k` 等公认简写
- `0`, `1`, `-1` 等用于基本运算逻辑的数学常量（如 `index + 1`、`size - 1`）
- 日志消息中的固定文本格式字符

### 12.2 条件语句约束

后端业务逻辑中，**`if...else if` 条件分支数量大于 3 时，必须重构为 `switch` 语句**（或策略模式）。

```java
// ❌ 错误：超过 3 个 if...else if 分支
public String getPhaseDescription(String phase) {
    if ("REQUIREMENT".equals(phase)) {
        return "需求阶段";
    } else if ("PROTOTYPE".equals(phase)) {
        return "原型阶段";
    } else if ("UI_DESIGN".equals(phase)) {
        return "UI设计阶段";
    } else if ("TECH_PLAN".equals(phase)) {
        return "技术方案阶段";
    } else if ("CODING".equals(phase)) {
        return "编码阶段";
    } else {
        return "未知阶段";
    }
}

// ✅ 正确：使用 switch 重构
public String getPhaseDescription(ProjectPhase phase) {
    return switch (phase) {
        case REQUIREMENT -> "需求阶段";
        case PROTOTYPE -> "原型阶段";
        case UI_DESIGN -> "UI设计阶段";
        case TECH_PLAN -> "技术方案阶段";
        case CODING -> "编码阶段";
    };
}
```

**补充**：若分支逻辑较复杂（每个分支 ≥10 行），进一步重构为**策略模式**（`Map<Enum, Handler>` 注册方式）。

### 12.3 方法行数约束

**单个方法代码行数不得超过 80 行**（不含空行和纯注释行）。

```java
// ❌ 错误：方法过长（>80行）
public ProjectResponse createProject(String userId, CreateProjectRequest request) {
    // ... 120 行代码
}

// ✅ 正确：拆分为多个职责单一的方法
public ProjectResponse createProject(String userId, CreateProjectRequest request) {
    validateQuota(userId);                                  // 抽取为独立方法
    Project project = buildProject(userId, request);        // 抽取为独立方法
    project = persistProject(project);                      // 抽取为独立方法
    triggerWorkflow(project, request);                      // 抽取为独立方法
    logCreation(project, userId);                           // 抽取为独立方法
    return projectConverter.toResponse(project);
}
```

**计数规则**：
- 统计有效代码行（不含纯空行、不含纯 `//` 或 `/* */` 注释行）
- 方法签名行 `public ... {` 计入
- 方法结束的 `}` 计入

### 12.4 嵌套层级约束

**单个方法内，循环语句（`for`/`while`/`forEach`）与 `if` 语句的嵌套深度不得超过两层**。

```java
// ❌ 错误：嵌套深度为 3 层
public void processItems(List<Project> projects) {
    for (Project project : projects) {             // 第1层
        if (project.isActive()) {                  // 第2层
            for (Item item : project.getItems()) { // 第3层 —— 超出！
                if (item.needsProcessing()) {      // 第4层 —— 超出！
                    item.process();
                }
            }
        }
    }
}

// ✅ 正确：使用提前返回 / 提取方法降低嵌套
public void processItems(List<Project> projects) {
    List<Project> active = projects.stream()
        .filter(Project::isActive)
        .toList();
    active.forEach(this::processProjectItems);       // 委托独立方法
}

private void processProjectItems(Project project) {
    project.getItems().stream()
        .filter(Item::needsProcessing)
        .forEach(Item::process);
}
```

**降低嵌套的策略**：
- **提前返回**（Guard Clause）：`if (!valid) return;`
- **提取方法**：将深层逻辑提取为独立方法
- **Stream API**：使用 `filter`/`map`/`flatMap` 替代嵌套循环
- **Optional**：用链式调用替代 `if (obj != null)` 嵌套

### 12.5 注释规范

#### 12.5.1 业务逻辑注释

**重要业务逻辑、复杂算法、非显而易见的处理**，必须编写行内注释或块注释说明意图。

```java
// ✅ 正确：关键逻辑附注释
public void settleOrder(Order order) {
    // 先冻结库存，再扣款，保证最终一致性——冻结失败直接回滚
    if (!inventoryService.freeze(order.getItems())) {
        throw new BusinessException(ErrorCode.INSUFFICIENT_STOCK);
    }

    // 使用乐观锁重试，最多 3 次，防止并发覆盖库存快照
    for (int retry = 0; retry < MAX_RETRY; retry++) {
        try {
            paymentService.charge(order);
            break;
        } catch (OptimisticLockException e) {
            if (retry == MAX_RETRY - 1) throw e;
        }
    }
}

// ❌ 错误：无注释的复杂逻辑（读者无法快速理解意图）
public void settleOrder(Order order) {
    if (!inventoryService.freeze(order.getItems())) {
        throw new BusinessException(ErrorCode.INSUFFICIENT_STOCK);
    }
    for (int retry = 0; retry < 3; retry++) {
        try { paymentService.charge(order); break; }
        catch (OptimisticLockException e) { if (retry == 2) throw e; }
    }
}
```

#### 12.5.3 类字段注释

**所有类字段（Entity、VO、DTO、Request、Response）** 必须编写注释说明字段含义。

```java
// ✅ 正确：每个字段有注释
@Entity
public class Project implements Serializable {

    /** 项目唯一标识（UUID v7） */
    @Id
    private String id;

    /** 项目名称，不允许重复 */
    @Column(nullable = false, length = 255)
    private String name;

    /** 项目当前状态 */
    @Enumerated(EnumType.STRING)
    private ProjectStatus status;

    /** 创建时间（UTC），不可更新 */
    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;

    /** 最后修改时间（UTC） */
    @Column(name = "updated_at")
    private LocalDateTime updatedAt;
}
```

#### 12.5.4 枚举值注释

**所有枚举类型**，必须为每个枚举值编写注释，说明其含义与用途。

```java
// ✅ 正确：逐一标注枚举值
public enum ProjectStatus {

    /** 草稿：项目已创建但尚未启动 AI 工作流 */
    DRAFT,

    /** 运行中：AI 工作流正在执行 */
    RUNNING,

    /** 已完成：全部工作流阶段执行完毕 */
    COMPLETED,

    FAILED,

    /** 已取消：用户主动终止项目 */
    CANCELLED
}

// ❌ 错误：枚举值无注释
public enum ProjectStatus {
    DRAFT, RUNNING, COMPLETED, FAILED, CANCELLED
}
```
